# Currency Exchange

Учебный проект для получения курсов валют и конвертации сумм. На текущем этапе реализован backend API; frontend пока не разработан.

API получает данные из Frankfurter, проверяет входные параметры и ответы внешнего сервиса. Конвертация рассчитывается на backend. Кеширования и таймаута внешних запросов пока нет.

## Технологии

- Node.js и TypeScript в строгом режиме.
- Express 5, CORS и dotenv.
- Встроенный `fetch` для обращения к внешнему API.
- npm workspaces для организации monorepo.

## Структура

- `backend` — API на Express и TypeScript.
- `frontend` — клиентское приложение (будет добавлено позднее).

## Установка и запуск

Нужны Node.js с поддержкой встроенного `fetch` и npm. Разработка проверялась на Node.js 24.

Установить зависимости из корня проекта:

```bash
npm install
```

Создай файл `backend/.env`:

```dotenv
SERVER_PORT=3000
FRANKFURTER_BASE_URL=https://api.frankfurter.dev/v2
```

Базовый URL указывай без завершающего `/`. Файл `.env` не хранится в Git.

Запустить backend в режиме разработки:

```bash
npm run dev:backend
```

Собрать все существующие приложения:

```bash
npm run build
```

Запустить собранный backend:

```bash
npm run start:backend
```

При указанном порте API доступен по адресу `http://localhost:3000/api`.

## API

Все успешные запросы возвращают JSON со статусом `200`. Примеры данных ниже иллюстративные: реальные значения и даты зависят от источника.

### Список валют

`GET /api/currencies`

Возвращает массив валют:

```json
[
  {
    "code": "EUR",
    "name": "Euro",
    "symbol": "€",
    "coverageEndDate": null
  }
]
```

`symbol` и `coverageEndDate` могут быть `null`. `coverageEndDate` соответствует полю `end_date` источника. Некорректные записи пропускаются; если не осталось корректных записей, API возвращает `502`.

### Курсы валют

`GET /api/rates?base=EUR`

Возвращает доступные курсы относительно обязательной базовой валюты `base`.

`GET /api/rates?base=EUR&quotes=USD,GBP`

Необязательный параметр `quotes` ограничивает список целевых валют. Коды разделяются запятыми, повторы удаляются. Переданный пустой список или некорректный код возвращает `400`.

```json
[
  {
    "date": "2026-10-02",
    "base": "EUR",
    "quote": "USD",
    "rate": 1.1
  }
]
```

`date` — дата курса из источника, не дата выполнения запроса. Некорректные записи курсов пропускаются; если корректных записей нет, API возвращает `502`.

### Конвертация суммы

`GET /api/convert?from=EUR&to=USD&amount=100`

Все три параметра обязательные:

- `from` — исходная валюта.
- `to` — одна целевая валюта, не список.
- `amount` — конечная положительная сумма. Принимаются целые числа и дроби с точкой: `100`, `12.50`, `0.001`. Ноль, отрицательные суммы, записи `0x10`, `1e3` и дроби с запятой отклоняются.

```json
{
  "from": "EUR",
  "to": "USD",
  "amount": 100,
  "rate": 1.1,
  "result": 110.00000000000001,
  "date": "2026-10-02"
}
```

Расчёт: `result = amount × rate`. Результат не округляется принудительно; возможны особенности точности чисел JavaScript, как в примере. Переполнение результата возвращает `400`.

Если нормализованные `from` и `to` совпадают, возвращаются курс `1`, исходная сумма и `date: null`, без внешнего запроса. В этой ветке проверяется формат кодов, но их поддержка источником не проверяется.

### Общие правила и ошибки

Коды валют нормализуются: пробелы по краям удаляются, буквы переводятся в верхний регистр. Каждый код должен содержать ровно три латинские буквы. Параметры, ожидающие одну строку, нельзя передавать повторно.

Ошибки возвращаются в едином формате:

```json
{
  "error": {
    "code": "BAD_REQUEST",
    "message": "Параметр amount должен быть конечным положительным числом"
  }
}
```

| Статус | Код | Причина |
| --- | --- | --- |
| `400` | `BAD_REQUEST` | Некорректные параметры, неподдерживаемая валюта при запросе курса или переполнение результата. |
| `404` | `NOT_FOUND` | Неизвестный маршрут. |
| `502` | `UPSTREAM_ERROR` | Сетевой сбой, ошибка внешнего API, некорректный ответ или отсутствие нужного курса. |
| `500` | `SERVER_ERROR` | Непредвиденная ошибка приложения или отсутствие обязательной конфигурации. |
